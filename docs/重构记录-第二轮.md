## 2. 架构变化：core 拆分为四个模块

```
BiliApplication
├── :app                      导航壳 + BottomBar + 主题装配
├── :core
│   ├── :model                纯 @Serializable 模型 + 路由 + QrPollStatus（无 Android 依赖逻辑）
│   ├── :common               工具（ZQRCodeUtils、uriToMultipartPart）
│   ├── :network              Retrofit/OkHttp/ApiService/Qualifiers/NetworkModule
│   └── :data                 仓储（Auth/User/Video）+ PagingSource + 会话 + 数据层 DI
└── :features
    ├── :designsystem         BiliTheme / BiliTypography / BiliColors
    ├── :login                扫码登录（注入 AuthRepository）
    └── :home                 顶部 MusicTopBar + 推荐流（注入 VideoRepository）
```

依赖方向（单向、无环）：

```
:core:model  ←  :core:network  ←  :core:data  ←  features:login / features:home
:core:model  ←  :core:common
features:*   →  :features:designsystem
:app         →  features:* + :core:model
```

关键决策：

- **OkHttpClient 放在 :core:data**：Cookie 拦截器依赖 BiliSessionManager（会话属于数据层），
  避免 network → data 的循环依赖；日志分级仍读 `core.network.BuildConfig.DEBUG`。
- **ApiService 按 baseUrl 拆分**（P1-9）：`BiliApiService`（api.bilibili.com，含 popular）与
  `BiliAppApiService`（app.bilibili.com，推荐流），运行时行为与原来完全一致，只是消除"一个接口两个域名"的歧义。
- **`@Binds` 取代 `@Provides`**：仓储实现全部为 `@Inject` 构造，接口用 `@Binds` 绑定（审计 P1-2 建议）。
- **统一异常**：新增 `BiliApiException(code, message)` + `biliApiCall {}` 辅助函数，所有 `BiliResponse<T>`
  接口的错误分支收敛为一行。

## 3. 模型合并

- 删除 `core/domain/model/` 全部 12 个 `*Domain` 副本与各网络模型的 `toDomain()` 映射（约 150 行模板代码）。
- 网络模型即领域模型：`BiliResponse`、`QrCodeData`、`QrPollData`、`RecommendItem`、`PopularItem`、
  `VideoDetail`、`ReplyData`、`UserInfo`、`LikeVideoData`、`HasLikeVideoData`、`PlayUrlData` 等统一在 `com.software.core.model`。
- `toDomain()` 里兜底默认值（如"未知观看"）改由 UI 层对可空字段做展示兜底（首页卡片已处理）。

| 原（10 个） | 现（3 个） |
| --- | --- |
| BiliQrCodeDataRepository / BlBlPollQrCodeStatusRepository / BiliSessionManager | **AuthRepository**（getQrCode / pollQrCodeStatus / saveSession / clearSession / cookieFlow） |
| BiliGetUserInfoRepository | **UserRepository**（getUserInfo） |
| BiliRecommendVideoRepository / BiliGetPopularListRepository / BiliGetVideoPlayUrlRepository / BiliGetVideoDetailRepository / BiliGetReplyListRepository / BiliLikeVideoRepository / BiliHasLikeVideoRepository | **VideoRepository**（推荐/热门分页流 + 播放地址 + 详情 + 评论 + 点赞） |

## 5. UseCase 层

- 删除 11 个纯透传 UseCase（`BiliQrCodeDataUseCase`、`BiliPollQrCodeStatusUseCase`、`BiliRecommendVideoUseCase`、
  `GetRecommendVideosUseCase`、`BiliGetPopularListUseCase`、`BiliGetVideoDetailUseCase`、`BiliGetVideoPlayUrlUseCase`、
  `BiliGetReplyListUseCase`、`BiliLikeVideoUseCase`、`BiliHasStatVideoUseCase`、`BiliGetUserInfoUseCase`）与 `BiliUseCaseModule`。
- 结论：该层只有转发没有规则，删掉后行为不变（审计 P1-2 的"只保留有规则的 UseCase"）。
- **唯一保留的"规则"下沉为 `QrPollStatus` 状态机**（core:model）：`code → WAITING_SCAN / WAITING_CONFIRM / EXPIRED / SUCCESS`，
  ViewModel 不再散落 86101/86090/86038 魔法数字。

## 10. BottomBar / MusicTopBar 企业级评审（你要求检查的部分）

### 10.1 结论

方向正确：`NavigationBar` + 类型安全路由 + `hasRoute()` 选中态是 Jetpack 官方推荐的底部导航写法；
MusicTopBar 用 `ScrollableTabRow` + 自定义指示器也合理。**但原实现存在 2 个 P0 级问题**，达不到可直接交付的水平。

### 10.2 原代码问题清单

| 级别 | 问题 | 影响 |
| --- | --- | --- |
| P0 | **路由映射错误**：4 个 Tab 中 Home/recommend/Profile 三个都指向 `DiscoverRoute` | 点"首页"永远高亮"推荐"，`hasRoute` 选中态失效，导航行为错乱 |
| P0 | `currentBackStackEntryAsState()` 写在 `forEach` 循环**内部** | 每个 Tab 独立订阅导航状态，重复 recomposition 源；状态提升后可读性也差 |
| P1 | 硬编码颜色 `Color.Red` / `0xFF333333` / `0xFFFF4D4D` | 违反设计 Token 原则，暗色模式无法适配 |
| P1 | 组件放在 `com.software.home.bottombar` | 底部导航是**全局导航壳**，不属于 home feature（分层错误） |
| P1 | 引用旧包 `com.software.core.navigation` | 包迁移后编译不过 |
| P1 | `TopLevelRoute` 未形成契约：label/icon 与路由散开写 | 加 Tab 时容易再次写错路由 |
| P2 | `popUpTo(graph.startDestinationId)` 用旧 API | navigation 2.9 中应使用 `findStartDestination()` |
| P2 | MusicTopBar 的 Tab 列表、Menu/Add 回调全部写死 | 无法复用/测试；`selectedIndex` 无记忆 |

### 10.3 修复方案（已落地）

- **BottomBar → `app/.../ui/BottomBar.kt`**（导航壳层）：
  - 新增 `TopLevelDestination(route, label, icon)` 契约，4 个 Tab 一一对应 4 个真实路由：
    首页 → `HomeRoute`（Home 图标）、推荐 → `DiscoverRoute`（PlayArrow）、收藏 → `LibraryRoute`（List）、我的 → `ProfileRoute`（Person）。
  - `currentBackStackEntryAsState()` 提升到循环外，循环内只读值。
  - `navigate` 使用 `popUpTo(findStartDestination().id) + saveState/restoreState + launchSingleTop`，各 Tab 状态互不丢失。
  - 选中态：`currentDestination.hasRoute(destination.route::class)`。
  - 仅在主界面显示（`AppNavHost` 判断当前路由是否属于一级 Tab，登录页不显示）。
- **MusicTopBar → `features/home/topbar/MusicTopBar.kt`**（home feature 专属）：
  - 颜色全部收敛到 `BiliColors` Token（指示器用品牌粉，文字主/次色，Add 用 AccentRed）。
  - Tab 列表与 Menu/Add 回调改为参数（默认 `博客/有声书/广播剧/听书`），可注入、可测试。
  - 逻辑不变：选中 Tab 字号/字重放大 + 底部小指示条。
- **导航骨架（AppNavHost）**：`Scaffold(bottomBar)` + `NavHost(LoginRoute 起始)`；
  登录成功 `navigate(HomeRoute) + popUpTo(LoginRoute){inclusive}` 清栈，底部导航自然出现。

### 10.4 企业级差距与后续建议

- 目前是"单模块企业级"：模块化、单向依赖、DI、UDF、Token 都已达标。
- 还差的部分（建议下一轮）：BottomBar/MusicTopBar 的 Compose UI 测试；无障碍（contentDescription 已加，建议加测试）；
  播放器迷你条（MusicTopBar 下方预留的"正在播放"条）等播放器能力接入后再补。

## 12. 构建验证

- 命令：`gradlew :app:assembleDebug`（JDK 17 / Gradle 9.4.1）
- 结果：**BUILD SUCCESSFUL**——`core:model` / `core:common` / `core:network` / `core:data` /
  `features:designsystem` / `features:home` / `features:login` / `app` 共 8 个模块全部编译通过，debug APK 产出成功。
- 过程中修复的编译问题（均已解决）：
  1. `core:data` 缺 okhttp 依赖（OkHttpClientModule）→ 补 `okhttp` + `logging-interceptor`；
  2. home 的 `LazyPagingItems` 列表改用 `items(count=...)` 成员函数（不依赖 paging-compose 扩展导入）；
  3. 两个 PagingSource 注入 ApiService 缺限定符（`@BiliAppNetwork` / `@BiliApiNetwork`）→ Hilt MissingBinding；
  4. `Icons.AutoMirrored.Filled.List` 在当前 BOM 的 material-icons 中不存在 → 回退 `Icons.Default.List`（仅弃用告警）。
- 剩余告警（不影响构建）：`Icons.Filled.List` 弃用提示（material-icons 1.7 迁移项）；SDK XML 版本提示（本机环境差异）。
