## 补充：崩溃修复记录

**2026-08-29 `BiliSessionManager` 启动 NPE 崩溃**

- 现象：启动即崩 `NullPointerException ... Flow.collect(...) on a null object reference`，
  栈指向 `BiliSessionManager$1.invokeSuspend(BiliSessionManager.kt:38)`（Dispatchers.IO）。
- 根因：**Kotlin 属性按源码顺序初始化**。`init { scope.launch { cachedCookie = cookieFlow.first() } }`
  位于 `cookieFlow` 声明之前；协程派发到 IO 工作线程后，构造函数此刻正阻塞在
  `context.dataStore` 首次创建（文件 I/O），IO 线程抢先读到尚未赋值的 `cookieFlow`（null）→ `first()` NPE。
- 修复：调整声明顺序——`jctFlow`/`cookieFlow` 先赋值、`init` 的 launch 放最后（赋值 happens-before 启动协程）；
  首次加载包一层 `runCatching`，DataStore 读盘失败时保持空 Cookie，不让协程异常击穿进程。
- 排查确认：全项目仅两处 `init` 块，`BiliLoginViewModel.init` 引用的字段均声明在前，无同类隐患。
- 验证：`:app:assembleDebug` BUILD SUCCESSFUL。

## 2. 逐项说明

### 2.1 构建配置（1~7）

- **support 库彻底清除**：`com.android.support:appcompat-v7`、`com.android.support.test:runner`、support 版 espresso 全部移除，`enableJetifier` 关闭。Compose 工程不需要这些，Jetifier 只是"转译税"。
- **`testInstrumentationRunner` 统一为 `androidx.test.runner.AndroidJUnitRunner`**：原先指向 support 类，跑 instrumented test 必崩。
- **Room 只留 KSP 一条通道**：删掉 `annotationProcessor` 重复编译。
- **core 瘦身**：core 的 main 代码经检索未使用 Compose / media3 / Room / navigation / work，全部移除；只保留数据层所需（Retrofit/OkHttp/Datastore/Paging/zxing/core-ktx/Hilt/序列化）。
- **补 `androidx.paging:paging-runtime`**：`Pager` 在这个包，原先只声明了 `paging-common`。
- **home/login 补 `buildFeatures { compose = true }`**：与 app 对齐，避免 Compose 编译配置不一致。

### 2.2 core 网络层（8~12）

- **拦截器不再阻塞**：原来每个请求都 `runBlocking { cookieFlow.first() }` 读 DataStore；现在 `BiliSessionManager` 维护 `cachedCookie` 内存镜像，拦截器同步读内存。启动时异步加载一次，登录/登出时同步更新。
- **passport 链路补全**：扫码登录用的 `passport.bilibili.com` Retrofit 之前没挂 OkHttpClient（无 UA/Referer/Cookie/日志），现在复用同一实例。
- **日志分级**：debug 打 BODY，release 只打 BASIC，避免生产包泄露 Cookie/Token。
- **PagingSource 注入化**：`BiliRecommendVideoRepositoryImpl` 不再 `new BiliRecommendPagingSource(apiService)`，改由 Hilt 注入；`BiliRepositoryModule` 绑定同步更新。

### 2.3 登录链路（13~16、18）

- **修复"登录成功无处可去"**：`AppNavHost.onLoginSuccess` 现在跳转 `HomeRoute` 并 `popUpTo(LoginRoute) { inclusive = true }` 清空返回栈；已登录用户（`checkLoginStatus`）走同一回调，同样进入首页。
- **移除未实现的密码登录**：审计建议"要么实现要么隐藏"，密码登录需要 RSA 加密（工作量不小），本次选择隐藏"账号登录"Tab，只保留扫码登录，避免给用户一个点了没反应的按钮。
- **二维码生成切 IO 线程**：512×512 逐像素生成不再阻塞主线程。
- **死代码清理**：注册功能残留字段、`qrPollData` 只写不读状态、密码输入事件全部移除。

### 2.4 首页与设计系统（17、19）

- **home 从空壳变为可用占位页**：`BiliHomeRoute`（hiltViewModel + UiState）→ `BiliHomeScreen`（无状态）+ `homeNavGraph()` 导航扩展。后续实现推荐流时替换 `BiliHomeScreen` 内容即可。
- **designsystem 首次落地**：新增 `BiliColors` 色彩 Token，login 界面的品牌色全部从硬编码改为引用 `BiliColors.BiliPink`。app 的 `ui/theme` 迁移到 designsystem 留待下一步（见 §4）。
